# Curriculate — Project Guide

## A. Pulse Grading — Core

**What:** AI grading tool for teachers. Photo/paste/batch/video/audio input → rubric-matched feedback → score + report.

**Key files:**
- `frontend/src/app/grading/page.jsx` — main grading UI (photo, paste, strictness, student/class pickers, rubric override, session email, response display)
- `frontend/src/app/grading/BatchGrading.jsx` — batch PDF grading (upload PDF → classify pages → grade each student → results grid)
- `frontend/src/app/grading/VideoGrading.jsx` — video performance grading
- `frontend/src/app/grading/AudioGrading.jsx` — audio performance grading (music, speeches, drama)
- `frontend/src/app/grading/pdfReports.js` — PDF report generation (half-page, strips, session summaries)
- `backend/index.js` — main backend; grading endpoints (`POST /grading`, `/grading/batch`, `/grading/check-rotation`), classification prompt, AI scoring logic
- `backend/models/GradingUsage.js` — usage tracking per teacher

**Features:**
- 5 input modes: photo, paste, batch PDF, video, audio
- 13 feedback voices + per-question audit toggle + rigorous review modifier
- Rubric override: paste, upload PDF/DOCX, or use auto-detected rubric from photos
- Saved rubrics (localStorage)
- Per-student strictness adjustment (chevron UI on results)
- Batch grading: PDF upload → AI classifies answer key / rubric / student pages → grades each student → results grid with re-grade
- PDF rotation handling: dedicated `/grading/check-rotation` endpoint with majority vote, retry logic, gpt-4.1
- Freeform/handwritten assignment classification support
- CurricQR-coded PDF reports for students
- Session email with PDF attachments + Edsby CSV export

## M. Daily Board (classroom projector)

**What:** `www.curriculate.net/daily` — a full-screen, one-class-per-screen board driven by the DisplayAI tab of the teacher's Google Sheet planner. Polls the sheet once a minute; every element (lesson text, status chips, class points, video tile, lesson picture, poem/riddle cell) comes from the sheet, and the timing rules come from its Setup tab. No site header/footer on this page.

**Key files:**
- `frontend/src/app/daily/page.jsx` — the board (clock phases, video tile, picture window, points strip)
- `frontend/src/app/daily/layout.tsx` — kiosk layout (fonts, noindex, hides chrome via `body.daily-kiosk`)
- `frontend/src/app/daily/daily.css` — projector-sized styles
- `frontend/src/app/api/daily/route.ts` — reads + parses the sheet; in-memory copy (`lib/daily/cache.ts`) re-read after 2 min or after a ping; optional `DAILY_ACCESS_KEY`
- `frontend/src/app/api/daily/ping/route.ts` — `?key=DAILY_PING_KEY`; the sheet's Apps Script on-edit trigger calls it so edits show within ~10 s
- Page polls every 10 s; bottom-edge time scrubber previews any time of day and snaps back to live after **5 minutes** (45 s took the screen back mid-sentence). Every class is a dot on the scrubber line and pressing one goes to the minute that class begins, so the afternoon is one press away rather than a careful drag
- The board evaluates the sheet's three NOW()-driven display rules itself (`evaluateFeature`, `evaluateDailyText`, `evaluateStatus` in `lib/daily/parse.ts`) instead of reading their results, so the scrubber moves them and an `=IMAGE()` slot is seen — the sheet's own `<>""` test skips picture slots, which is why E1 showed nothing
- **The Setup slot rules are evaluated, not read** (`lib/daily/formula.ts`): each slot's row 4 in `Setup!S1:AB8` is a NOW()-driven rule — the CE memory verse for the first ten minutes, the picture in S2 on the week's last teaching day — and reading the cell gave the answer for the instant of the read, so the scrubber could not move E1. A Sheets evaluator re-runs them with NOW() bound to the time on the board: IF/IFS/AND/OR, NOW/TODAY/TIMEVALUE/WEEKDAY/DATEVALUE/DAYS/TEXT, INDEX (a missing row or column meaning the whole of it), MATCH, HLOOKUP/VLOOKUP, FILTER, ROW/COLUMN, JOIN, INDIRECT, LET and LAMBDA, the text and maths functions, cell and range references, and arrays that spread across comparisons and arithmetic the way Sheets spreads them. RANDBETWEEN is fixed for the day, or a projector re-rendering every few seconds would make the line jump about. It reaches `Setup!A1:P40`, `Setup!M1:Q8`, `Setup!S1:AB8`, `Display!A1:F20`, `Poems!A1:B60` and `F1:J3`, `MemoryCards!H1:H40`, `Vocab!A1:B60`, `Master!A1:K2`, `Subjects!U1:U40`, `MathChallenge!A1:C60`, and the heads of `Vertical` and `VerticalAi`; a reference past those, or a function it does not know, falls back to the value the sheet computed. A slot whose row 4 is only a value keeps its rule in row 5 — the daily update is generated there and pasted into row 4 — so row 5 is run instead, which is the difference between today's text and whatever was pasted last term. Row 3 is the slot's own material and row 4 the rule that gates it; `?debug=1` prints both for every slot
- The status is a privilege code shown as a coloured bubble mirroring the sheet's conditional formatting on D9/D11/D13 (`statusStyle`). It says what the benefit is (`statusWords`, `BENEFIT_WORDS`) and only while that benefit is on the table: **Free seat** (B1) for the opening minutes of the class (Setup "Free seat for", 5 by default), **Free pass** (B2) and **Extra FD** (B3) from Setup's grace minutes (15) to the end, **All 3** for the whole class from its first minute. A trailing 4 adds "+2" for a perfect class. The colour is worked out from what is on offer — the code is rebuilt in the sheet's shorthand and put through the same rules — and the bubble is not drawn when nothing is available. The group letter sits small beside the words and the raw code stays in the tooltip. A code with no text label (`A-1000`) is read as its digits, in the legend's order — Benefit 1, 2, 3 — instead of reading as nothing. The Washroom chip shares the pass's opening window and counts down to it
- **The reward thresholds come from the sheet** (`Setup!D52:AE56`, `parseRewardRules`): a header row then one row per benefit, the rule in words on the left and its numbers on the right — B1 Sit Anywhere/snack at 9 points over 5 days, B2 the washroom pass at 9 over 2, B3 Extra Formal Discussion on an average of 8.5 over at least 4, and C1 (W1 before it was renamed) the writing penalty at below 6 points twice in the previous 2 days. A row is found by its label and its numbers by the header above them (`Pnts`, `Days`) rather than by how far along they sit: the block has hidden columns in it, and revealing one moves every number a place to the right. The first three the sheet works out itself and writes into Points row 46, so the board only reads them; the last it does not, so the board computes it from these numbers rather than from a rule repeated by hand. `?debug=1` prints all four as read
- **Benefit 3 — the earned extra Formal Discussion — is read from the sheet's own flag** (`b3Earned`): each class block on the Points tab carries four flags nine to twelve columns right of its name — B1, B2, P1, then **B3 in column P** — and the sheet works B3 out per week row as `=iferror(if(and(average(D6:H7)>=$Z$55,countifs(D6:H7,">0")>=$AA$55),1,0),"")`: the average of the last two weeks of day cells against B3's points, and the days actually scored in them against B3's days. The board takes that flag where the column carries one and runs the same test over the day cells where it does not, which is the state the Totals beside it were in all last term. AVERAGE counts a nought and COUNTIFS(">0") does not, so a day thrown away lowers the average without counting towards the days; that is the sheet's arithmetic and it is kept. **The days figure assumes a class that meets every day** (`Points!AD55`), so it is prorated against how often the class actually meets — row 3, three columns right of the name (`G3`, `T3`, `AG3`) — or a class taught twice a week could never earn it: four days of a five-day week is 1.6 of a two-day one. The threshold block is read from **both** `Setup!D52:AE56` and `Points!D52:AE56`, the Points copy answering first because the sheet's own flag is written against it (its formula names `Z55` and `AA55` with no tab in front of them). The extra discussion then hangs off this as well as off the privilege code, so it is known outside the minutes when a code is showing. `?debug=1` prints which classes have earned it and the working behind each
- The legend's writing penalty is the one rule the sheet does not compute, so the board does (`writingOwed`): C1's rule — as many days below C1's points as it names, inside its span of scored days — puts a brown **Writing** chip beside that class. It reads the day cells themselves — each class block's Monday-to-Friday columns, a week per row from row 6 — not a column it goes looking for. It used to sniff out "the column in this block that reads like daily scores" and settle on the **Total** column beside them, forty rows of noughts against three real day cells, so it watched a column that could never show a poor day and the chip could never appear. A day counts once it has been scored: blanks, the `x` and `-` that mark a day the class does not meet, and noughts are all passed over, since a chip that accuses a class should not rest on a row that is only waiting for the rest of the year. `?debug=1` prints the days it weighed for each class and the rule it weighed them against
- The between-classes screen ("Change of class") only says **Day complete** when the day actually is complete — past the day's last bell — and otherwise "Nothing scheduled", because it was claiming the day was over at ten in the morning. With no class after this one it shows the day itself — the classes on the board, else the day's plan, else the timetable rows — rather than a lone caption on an empty screen, so it is plain at a glance whether the gap is the timetable or the sheet
- The "Today" panel does not carry another class's lesson: when the day's text is the whole plan, one class after another, shortening it to its first lines always gave the *first* class of the day — so the History screen showed Math's blurb under a heading reading "Today". During a class that panel is left out altogether, since the class is the screen; between classes the plan still shows. A genuine daily note is unaffected
- Persistent next-class peek line (subject, room, time) under the period line
- Each subject carries its own colour (`subjectTheme` in `lib/daily/parse.ts`, keyed off the lesson code letter) — heading wash, chips, progress bar and panel edge follow it, so a class change is visible from the back of the room; the footer day chip uses the sheet's own weekday colours (`weekdayColour`)
- The clock is highlighted (red pill, slow pulse) for the last few minutes of a period — the window is Setup's "change time to red" (5 min if that row is missing) — and the peek line turns red and reads "Next in N min: …", naming the next row of the timetable (lunch and recess included), or Dismissal after the last class; it applies to breaks too, measured to the end of the break
- A class holds the screen to its very last minute: the dismissal screen waits for the current period to finish rather than taking over at the dismissal time, which can fall inside the final period
- End-of-day package: for the last few minutes of the day (Setup's "For Dismissal Messages" block, columns N to Q — the times and how many minutes ahead) E1's side of the screen becomes what's on tomorrow (the "Tomorrow:" header cell), the "Before you head out" list (C15) and the Kiss & Ride waiting list; the "Pray for …" line also comes forward, highlighted, before each of those times. At dismissal the screen carries the goodbye, then **the blessing** where the verse used to be — the verse has had the bottom bar all day and the last word belongs to the blessing — then the standing-ready note (tidy the area, tuck the chair in, stand behind it), the head-out list, tomorrow, the waiting list and whatever E1 holds, with the unscramble puzzle in the bottom bar
- The dismissal panel leads with "Get ready for dismissal" — tidy up, tuck the chair in, stand behind it ready for the homeroom teacher — for the last few minutes before the day's last bell (Setup's "Stand ready for dismissal" row, five minutes if it is absent, as it is in the sheet today). Setup is read as `A1:F20`, labels in column B and values in C/D
- The Kiss & Ride tab is found by name at read time (`listSheetTitles` in `lib/daily/sheets.ts`), and its "Waiting (Recent First)" column is located by its header cell, so renaming either does not silently empty the panel
- End of the day = the DisplayAI dismissal row, else the Dismissal entry in the message block, else Setup's "Show Dismissal List", and only then the last bell — Vertical's time column runs on past the school day, so taking the last bell ahead of the sheet's own "Dismissal" put the end of the day at 4:25 PM and ran the class screens an hour past home time; that branch is checked before the "No classes today" one, which the board used to fall through to once the last row had passed
- The verse (A5) is evaluated too: the board reads Verses!A and Vertical!B4, strips the cell's lead-in at `~` so what gets shortened is the scripture rather than the introduction, and cuts at a word boundary (`truncateWords`) instead of A5's LEFT(…, 85); it shows in full for the 20 minutes from A9 and again from A11, as the formula does. If the Verses tab cannot be read, the A5 value is tidied back to the last whole word (`tidyTruncated`)
- At the end of the day the bottom bar shows the unscramble if the sheet has one, otherwise a riddle — the sheet's own, or one of the built-in `HOUSE_RIDDLES` picked by the date — since the verse is already large on the dismissal screen. **The answer rides at the far end of that line, in red**: out past the right edge until the sweep reaches it, so the room gets a moment to think before it arrives, and gone again when the line slides back. It comes from `Riddles!E` on the same row as the riddle, which is why that read is `D1:E400`; the built-in riddles carry their own answers. A riddle short enough not to sweep keeps its answer hidden too — it fades in at the same point of the minute
- Handouts for the class on screen show as clickable chips under the lesson bullets, so a print run that was forgotten can be started from the board. They come from URLs written into the lesson cell (`extractLinks`) and from rich-text links attached to phrases in it (`readCellLinkRuns` over `DisplayAI!C1:C40`); the name is taken from the words nearest that link — since the previous link, back to the last sentence break — falling back to the kind of file. Links are deduped by what they point at (`canonicalUrl`), so the same Google file written `/edit?tab=t.0`, `/edit?usp=sharing` and `/edit` is one chip. The addresses are stripped out of the bullets, which also stops a URL's own `?` being read as the lesson's question
- **The class heading links to the course's deck.** The row above a course's first lesson carries the year's presentation deck in **column B** — written out, in a `=HYPERLINK()`, or attached to that cell's text — and every lesson of that course carries it, so "History 7A" at the top of the screen opens it (`parseLessons`, `deck`). The reads gain `Lessons!B1:B400` as a value and a formula, and the grid read widens to `Lessons!B1:K400`; the link runs are therefore B-based, so E is index 3 and F index 4
- **The day's first class starts when the opening is over** (`firstClassStart`): the room is standing through the announcements and O Canada, so a class whose row carries an earlier time begins at the first bell in Vertical column A at or after the anthem ends — 9:05 in the sheet — or at the anthem's end if the column has no bell there. A period that finishes before the opening does, or that the opening would leave a sliver of, is left alone
- The teacher's own material comes from the **Lessons** tab, keyed by the lesson code in column C (`~H001` or `H001`): E the starting page reference (a chip beside the room), F the homework (its links become handout chips, its text fills "Write in your agenda"), and at the end of the row the picture and the video. Those two are read for **what they hold, not by position**: every URL in I to K is gathered, the one that looks like a video is the video, and the picture is what is left — so a mirror column inserted between them, or taken out again, cannot make the board show a video where a picture belongs. The read is `C1:K400`. The student-facing tabs leave all of this out on purpose (`parseLessons` in `lib/daily/parse.ts`). Any URL there is taken, including a Drive link written `open?id=…` (which passes no image test) and a link attached to the cell's own text — the grid read covers `Lessons!E1:K400` for that. The picture takes the large side of the screen for the first `picSeconds` (10 min) of the class; `?debug=1` prints what was found and whether it loaded
- **DisplayAI and the day's plan are merged, not either/or.** DisplayAI fills from the sheet's own clock, so at half past nine it carries one class and the rest of the day is not in it yet; using it alone made the board believe the day ended after that class ("Change of class", "Day complete", at ten in the morning). The plan supplies every class DisplayAI has no row for, and DisplayAI — the live, AI-written version — wins for the periods it does carry, with the plan filling in only the code, page, picture and handouts that row lacks. The day's plan is on **VerticalAi columns F to J** (Monday to Friday, the day's classes run together in one cell): `classesFromText` finds each class header and parses the chunk after it, `dayPlanByWeekday` does it per weekday. **Vertical** carries the same columns with the period times in column A, so a row with both a time and a class gives that class its time; timed rows win the dedupe over a run-together copy, and a codeless echo of a coded class is dropped. The AI-written column does not always keep the lesson code, so the codes for each subject are collected from Vertical's own column and handed, in order, to any class that arrives without one — which is what lets a class from VerticalAi reach its Lessons row. The lesson code is optional in a class header, because that text writes some classes without one, and the subject is one word so a duty word before it ("Playground CE 8A") is not swallowed
- **Vertical writes a lesson in a different shape from DisplayAI's** — the header line, then a line carrying the code after a bullet and the lesson's title after a colon, then the activities, then an `[Assign: …]` block — so `parseClassText` reads that shape whenever the text announces it — a bullet-marked code line or an `[Assign: …]` block — rather than waiting for the DisplayAI patterns to find nothing, which failed on a title that happens to end in a question mark. Bulleted points inside the Assign block become separate assignments, and emoji come out while the bullet characters stay (`verticalLesson`). Line breaks are preserved through `extractLinks` and `classesFromText` because the shape is what tells the title from the activities
- Vertical is the spine of the day's plan — it carries the times and the codes — but it is the teacher's shorthand; **VerticalAi is the same lessons written for the room**, so where both describe a class the AI wording is what shows (`asWritten` in `dayPlanByWeekday`), with Vertical's time, code and room kept
- **Vertical column A is the bell schedule** (`bellSchedule`): a time is taken only while it is a school-day time and later than the one before it, so the first value that breaks that run ends the schedule — the column carries other things further down, and a stray value became a bell that cut a class short. No period is clamped to less than `MIN_PERIOD_MIN`. A class shorter than that is dropped outright and the class before it takes the time: the column carries bells left over from years with a class in that minute, and each one became a one-minute period repeating the class before it — "10:00 Math 7A, 10:59 Math 7A" on the agenda. Every period runs to the next bell, whatever rows DisplayAI happens to carry — without that a recess row whose next DisplayAI row was an hour away stretched over the classes in between. It is also where a plan class with no time can be placed
- A plan class with no time is placed in the next free bell time after the class before it (one no timed class has taken and DisplayAI has not named), so an afternoon Vertical gives no times for still appears rather than vanishing
- The head-out cell is recognised however the sheet writes it (`HEADOUT_CELL`): "Before you head out today…", "Before you go today, please:", "Make sure…". An unrecognised shape did not merely lose the list — that row carries a time in column A, so it became a period of its own, "1:00 AM · Before you go today, please: …" sitting in the middle of the day's timetable
- "Before you head out" belongs to the dismissal window, not to the last class on the board — before lunch the board says a grace instead (`LUNCH_GRACE`), inside the same "For Dismissal Messages" window
- A day whose lessons come from the plan runs the board's ordinary class screens: `periodsFromPlan` in `page.jsx` turns the timed plan into periods, each running to the next boundary (the next planned class, or the next time row DisplayAI does carry, which keeps lunch and recess in place), so the scrubber moves between them — 11:00 AM shows the 11:00 AM class — instead of one static list
- The points strip and the bottom line are sized to be read from the back of the room, and the bottom line stays on one row: the week line and the "Pray for …" link keep their space and the verse gives way
- The points strip is built from the cells the sheet's own plans line is built out of (`pointsFromSetup`): rows 35 to 40 of Setup, F the class, **K its total and L its percentage**. The line alternates between the two by the minute because one cell can hold one number at a time; the board holds the pair but shows one at a time on the same beat — six classes with two figures each is a row of small print — swapping on the minute off its own clock, so the scrubber moves it like everything else. Which figure is on is said once at the left of the strip rather than marked on every chip, and which of the pair is the percentage is decided by the cell carrying the `%`, not by the column it sits in. A class counts only where its column in Points row 2 has something — G, T, AG, AT, BG, BT, every thirteenth column — which is the same test the line makes, so a section not taught this year drops out. Both ranges are already read, so this costs nothing. A class with no figure stays empty and shows a dash rather than becoming a nought, which would read as a class that scored nothing. `?debug=1` prints what those six rows actually held, cell by cell, so a wrong answer can be told from a wrong place to look
- **When those cells read nought, the board adds the Points tab up itself** (`pointsFromGrid`). Each class has a block on that tab: the name in row 3 at D/Q/AD/AQ/BD/BQ, its target two columns on (240 for 7A, 320 for 7B, 160, 400, 160), the days it meets one further on again, then a week per row from row 6 — Monday to Friday, and a Total column the sheet computes. Setup rows 35 to 40 are built from those Totals, and every weekly Total reads 0 while the day cells beside it still hold 10, 10, 10 — so the sheet's own plans line and the strip both showed five classes on 0%. (Row 5 of that tab is `#REF!`, but deliberately so: they are old array formulae kept for reference, and nothing on the board reads that row.) The days are therefore added up here and the percentage taken against the class's own target — 7A's 30 out of 240 is the 13% the line used to show. It is a fallback, not a replacement: the moment Setup's own cells carry figures again they are what shows, and `?debug=1` says which of the two the figures came from
- **The strip's "Points in / Points missing" chip and the privilege bubble are both the sheet's own cells, and `?debug=1` now names them.** The chip is column D of the plans row (`enteredCell`), printed raw beside what the board made of it; the bubble comes from Points row 46, and the debug line gives each class's four flag cells by address and value — `7A: B1 M46=1 · B2 N46=1 · P1 O46=0 · B3 P46=0`. When the board says a benefit is on that a class has not earned, or says the points are missing when they are plainly in, that line says whether the board is reading the wrong cell or the sheet is saying so
- `?debug=1` also prints **every cell of `Points!A1:BV46` that holds anything** (`nonEmptyCells`), capped, so whether the strip is reading the wrong place or the sheet is genuinely empty is not a thing to answer from a photograph of a projector
- The plans line is still parsed as the fallback, and for its title, which past four o'clock reads "That's it for …" rather than "Plans for …" — the board did not recognise that and lost the title and the points-entered flag every afternoon. Each class's total is written `-value-` there and neighbours may share the dash between them, so the values are split on the dash (a run of three dashes is a negative value) rather than matched — matching swallowed the dash that started the next value and showed four classes as two. Points row 3 names the classes when the Setup rows do not
- **The screen is a column, and the lesson area is what grows** (`.board`): it was a grid with the spare space pinned to the third row, which held only while the screen had exactly the rows it was written for. The calendar banner and the birthday band each add one, so on the sparse dismissal screen the third row *was* the banner — a hand's depth of pale yellow across the projector with one line of text at the top of it. The board is a flex column now, everything sized to its content and `.main` taking what is left (and giving way first when a day's screen carries more than fits, since the bottom bar and the points strip must stay on the screen). Which row grows should not depend on how many rows there happen to be
- The board's grid column track is pinned to `minmax(0, 1fr)` and so are the lesson area's, or a long word grows the track, the whole board is laid out for a screen wider than the screen, and the overflow is clipped — which is what made the type look small with half the screen empty. An empty panel column is skipped when measuring the fit (stretched to the row, it reported a full screen) and the lesson takes the whole width when there is nothing to put beside it
- A lesson written without a question leads with what it is about rather than repeating the class name; and when a lesson is a title and an assignment with no activities, the assignment goes in the lesson column instead of leaving that half of the screen empty
- The lesson area fills the screen: after each render the board measures how far its content actually reaches and scales a `--fit` multiplier (0.75 to 1.9) on the content type until it just fits, so a sparse screen is not a page of white space and a crowded one still needs no scrolling. A picture column is elastic and left out of the reckoning; `.main` still clips as a backstop
- Before the first class the board lists the day's materials — every class's handouts, named by class — as clickable chips under the agenda, so they can be printed on the way in
- **The before-school agenda says what each class is about**, not just when it is: under "History 7A · Rm 202 · p. 2" sits the lesson in one line (`lessonLine`, `agendaRow` in `page.jsx`) — the question the lesson asks, else what it is about, else its first activity, which is the same choice the class screen itself makes. It is the one screen where the whole day is laid out, and a list of names and rooms said nothing about what the day held. The line is quieter than the class, and cut with an ellipsis rather than pushing the agenda off the screen; the day-plan agenda on the "no lessons filled in yet" screen uses the same row
- The greeting (A1) is evaluated too (`evaluateGreeting`): "Good morning" / "Enjoy your lunch" past 11:55 / "Good afternoon" up to the dismissal time / "Goodbye", plus the weekday's name from Setup column M — so it moves with the scrubber like the rest
- **The verse of the day has the right-hand half, on every class and on the day's own screens** (`verseBlock`, `versePanel`): the bottom bar carries it all day in passing, and this is where the room can actually read it. On a class it closes the panel, under the blocks the class needs first, and is set a size down — at the memory verse's size a five-block panel pushed it off the bottom of the screen, which is the one thing on that half that was asked for. On a day screen it has a half to itself at full size, the narrower half, since the day itself — agenda, materials, notices — is what the wider one is for. `FIT_MIN` came down to 0.55 so a crowded panel shrinks rather than clips
- **The Prayercast has the half straight after O Canada** (`prayerOn`, `prayerPanel`): the room is still standing and still together, so for `prayerMin` minutes from the anthem's end (Setup "Prayercast for", 5) the day's "Pray for …" cell — the same header cell and link the bottom bar carries all day — takes the right-hand half: the country's name and a tile big enough to press from across the room, a player where the link is a video and a card that opens in a tab where it is Prayercast's own page. The bar shows the country in plain text for those minutes, because two tiles of one video are two players. **The player is rendered at the foot of the board, not in the panel**: the header and the lesson area both carry a transform (the settle animation), which makes them the containing block for anything absolutely positioned inside them — a `position: fixed` overlay included — and `.vid`'s own `align-self: center` then sized the expanded tile to its content and centred it, four pixels of border with the insets ignored. That is why the lesson video never expanded properly either; both now open over the whole board
- **The half is handed on, and the verse is only ever in one place.** On a class it goes in order — the lesson picture for its window, the memory work in CE, then the verse of the day for `verseMin` (Setup "Verse of the day for", 10), whose own minutes start when it actually appears rather than when the class does — and then the half turns over to **the work**: that class's assignment, else its homework (`workOf`, `workBlock`). Where the panel is already saying that, the verse simply steps aside; where there is nothing to turn over to it stays, since an empty half helps no one. The day's own screens have no beginning to measure from, so there the verse and **"Set for today"** — every class that has something set, named (`dayWorkPanel`) — alternate on the board's own clock, and the scrubber moves them. **The bottom bar carries whichever the panel does not** (`verseUp`): while a verse holds the half — the verse of the day, or the memory verse in CE — the bar carries a success tip instead (`HOUSE_TIPS`, picked by the day and the class so it holds still while it is up), and takes the verse back, sweeping on the minute, the moment the panel gives it up. Scripture along the bottom of scripture is a line the room reads in neither place
- The verse in the bottom bar carries the whole quotation and sweeps across and back when it is longer than the bar, rather than ending in an ellipsis — **once a minute, or when it is pressed** (`sweepNow`, `sweepKey`), not endlessly: a line that never stops moving in the corner of a projector is one the room learns to ignore, and it carried the riddle's answer past before anyone had read it. The distance is measured, so a line that fits sits still. The measurement happens when the line itself arrives (a callback ref) and again whenever the bar resizes — an effect that only ran on the minute measured while the board was still on "Contacting the sheet…", found no line, and called it a line that fits. The sweep restarts by giving the inner span a fresh key, since a class put on by hand does not survive React rebuilding that node; the key is the whole minute, because the board's `live` carries the seconds as a fraction and the sweep never got past its first second
- Panel blocks do not shrink (`.panel > .block { flex: 0 0 auto }`): as flex items they used to compress and clip their own text, and the fit measurement reads where the blocks reach, so it saw a screen that fitted while the room saw a sentence cut in half. `FIT_MIN` is 0.66 so a full opening screen can still be made to fit
- A picture that fails to load is dropped for the rest of the page's life, and a projector page runs all day — so a fresh read of the sheet clears that memory and gives a re-shared Drive image another chance
- A header cell starting with "Pray" (with its hyperlink) shows in the bottom bar as a link, or as a small enlarging player when it points at a video
- One refresh is three Sheets requests — a values batch, a formula batch and one grid read (a fourth, once, on the refresh that first discovers a tab a rule names) (`readGridLinks`, serving both the "Pray for …" link and the lesson-cell handouts) — with the tab list cached an hour. Google allows 60 reads a minute per user, so a refresh happens at most once every 20 s even when a sheet edit has pinged, and a 429 puts the board on a 90 s hold serving the last read. `readRangesSafe` drops any range whose tab is not in the cached tab list before the batch is sent, so an optional tab the sheet does not have — `BoardImages` before the script has ever run, `MemoryCards`, `Vocab` — never reaches Google. That matters: it used to answer a 400 by probing every range on its own, and with two dozen ranges that is two dozen requests against a quota of sixty a minute, so one missing tab spent the allowance and turned a 400 into a 429 and the board into "the sheet could not be read". If a 400 still comes back, Google's message names the range it could not parse (`rangeFromError`); that one is remembered and the batch retried, at most a few times
- **The dot means what is on screen has gone stale, not that a fetch failed.** A cold serverless instance behind an 81 MB workbook can take half a minute to answer while the board carries a copy from ten seconds ago — a mark on a projector for nothing. So three failures in a row are necessary but not sufficient: the copy on screen must also be more than ten minutes old (`STALE_AFTER_MS`), and its age is reckoned from when the sheet was read, not when the page fetched it (`cachedFor`, and the `fetchedAt` of a copy painted out of `localStorage`). The tooltip then says how long it has been
- **A cold instance reads the quick half first.** With nothing to show, the route skips the two grid reads (`readGridLinks` over DisplayAI and `Lessons!B1:K400` — `includeGridData` on a workbook that size is the slow half of a refresh) and the discovery of any range a rule newly names. What they carry is handout links and course decks, not the lesson. The copy is marked `partial` on the cache, which counts as stale, so the next poll ten seconds later fills it in
- **A read that fails says so with a dot, not a sentence.** "The sheet took too long to answer" across the bottom of the projector is of no use to the room, so a failure is a small pulsing dot beside the week line with the whole message in its tooltip (and in `?debug=1`). The cause is addressed as well as the wording: reads no longer overlap — the board fired one every ten seconds whatever was happening, so a slow read had two or three piled up behind it, each making the next slower and each timing out in turn — a failed read backs off (10 s doubling to 60 s) rather than hammering a sheet that is already struggling, and nothing is said on screen until three reads have failed running, since one missed poll says nothing about a copy that is still today's. The in-flight flag belongs to the effect, not to the page: on a ref, a remount found the previous run's read still going, declined to start its own, and the board never polled again
- **The board does not wait for Google.** A copy in hand is served at once and the sheet re-read behind the response (`refreshSoon` in the route, one read at a time, the marker given up after a minute in case a frozen serverless instance never resumes it) — waiting for the read made every third or fourth poll take as long as the slowest thing Google did that minute, and on a projector that is a screen that sits there. Only a cold instance with nothing to show waits. The browser keeps the last copy as well (`daily:last` in `localStorage`) and paints it immediately when the board is opened, but only if it was fetched today — yesterday's copy would put yesterday's lesson on the wall. A payload is about 35 KB, and it is written only when the version changes
- `/daily?debug=1` shows exactly what the board received from the sheet — first stop when something in the sheet is not appearing. **Copy all of this** at the top copies the whole page as text, because every one of those lines was being read back off a photograph of the screen. It lists every picture the board holds — E1, the flag, and each class's — with whether it actually loaded
- **O Canada** holds the screen for the five minutes after the announcements (Setup's "O Canada for", 5 if the row is absent): the words on one side and the flag on the other, taken from the day's own column of `Poems!F1:J3` — F is Monday and J Friday, and the column carries whichever language that day sings in (`anthemOfDay`). **The announcements carry the same screen**, rather than a blank one with "Please listen" on it: the room is already standing, and the words are wanted before the anthem starts, not five minutes into it. The flag can be written into the cell (`=IMAGE("…")`, a link, or the address itself) *or picked by a rule* — `=IMAGE(INDEX(Flags!B:B, …))` is run and its answer taken (`imageFromRule`), which is what a sheet that keeps its pictures in a list needs; a picture *put into* the cell still needs **Pictures the API cannot see** below. `?debug=1` prints the window, the flag it found, how many lines of words, and the day column's three cells as formulas
- **The Formal Discussion** (`formalDiscussion`, `fdSlotForSection`, `weekOfMonth`, `impromptuTopic`): once a month every class group has one, announced at the start of the class in a violet box of its own beside the lesson. It falls in the **second week of the month** — the week whose Monday is the month's second — on the day of the group's **last discussion-subject class of the week** — History for a grade 7 group, Geography for a grade 8 one, which is how the timetable runs — so they have had the week's lessons before they talk. Taking either subject for either grade would let a stray "Geography 7A" choose the day. The subject is a preference, not a condition: on that day it goes in that period if there is one, and otherwise in whatever class of theirs is on — the last of the day. A group taught neither takes the day of their last class of the week. The topic comes from the **Impromptu** tab by row: column L for a grade 7 group, M for a grade 8 one, the row being the month (September is row 9). A group that has earned **Benefit 3** gets a second one, in any other week of that month once they qualify, from the month plus fourteen (September is row 23), and the box congratulates them. Once an earned one has been on the screen it has been had: the browser remembers it (`daily:fd-extra` in `localStorage`, by group and month) and it does not come round again that month, though it stays up for the rest of the day it appeared on rather than vanishing mid-class. A scrubbed preview never uses one up — only the live board records. The read is `Impromptu!L1:M30`
- **The memory verse and the hymn belong to CE, not to every class.** For the first `memoryMin` minutes (Setup "Memory verse for", 10 by default — 12:55 to 1:05 in this timetable) the right-hand half of the CE period carries the week's memory verse, and **the hymn's first verse under it in a colour of its own** so the two do not read as one block of text. The class is found by its subject (`/^CE\b/`), falling back to the fourth class of the day. The verse is joined from `MemoryCards` column H (`memoryVerse`); the hymn is indexed out of `Poems` by the week — column B rather than A when `Setup!C19` says so (`poemOfWeek`) — and cut to its first verse at the blank line (`firstVerse`), keeping the line breaks the sheet typed, since a hymn is lines rather than a paragraph. **Not on the day the verse is tested** (`testWeekday` — Friday as a rule, Thursday when Friday is off): on it the hymn has the half to itself with "verse test today" beside its heading. For those minutes the memory work takes the half over the lesson picture, which has its own window later in the class
- **The day's notices (`DisplayAI!A2`) reach the room.** Whose birthday it is, what is on at school today and — past noon — what is on tomorrow. Nothing claimed that cell and nothing showed it, so it never left the sheet. It is taken by position rather than pattern (it has no shape of its own, being whatever the calendar says) and only when row 1's greeting, row 3's week line and the `Tomorrow:` header have not claimed it. Its rule turns over at noon, so the board runs it at its own clock (`evaluateNotice`) and the scrubber moves it; the rule reaches into `Bdays` and `SchoolCalendar`, which get read because it names them. It shows as a sun-coloured block on the class panel and on the before-school screen
- **A birthday puts balloons over that grade's classes** (`birthdaysToday`, `birthdaysForSection`, `joinNames`): a band across the top of the class screen reading "Happy birthday, …", on the grade 7 classes for a grade 7 student and the grade 8 ones for a grade 8 student. The BDays tab is read by name: a row is today's when a cell carries the day as `"<serial> n"`, the name is the tenth cell of that block (where the sheet's own lookup takes it) and the grade is whatever cell in the row reads 7, 8, 7A or 8B — detected rather than read from a fixed column, since the layout is the sheet's own. **Column K is the school day a weekend birthday is kept on**, so where K carries a date it is K that decides and the birthday's own date does not — a Saturday birthday is not put up on the Saturday and not missed on the Friday — and **column L is the note** ("Saturday's birthday"), which the band says quietly beside the names. K is read as a serial, as the `"<serial> n"` key, or as a date in words; a bare number is not a date (`new Date("12")` is the first of December), so a week number in that cell leaves the row on its own day. The key column is found from the whole block rather than from the row in hand, because a row matched through K has some other date in its own key cell. `?debug=1` prints the names, grades and notes found
- **A banner says what is on today and what is on the next school day** (`calendarEvents`, `forTheRoom`, `specialDays`): a line across the top of every screen — the class, the announcements, the between-classes screen, dismissal — with the day's events and the next ones, so a PD day or a dress-down is known about before it arrives. "Tomorrow" is the next day the room is actually in, not the next date: on a Friday it reads **Monday**, and a weekend says nothing. A day off on the way there is announced in its own right, by name and in the alert colour, and the walk carries on to the day they are next in, so "Monday — No school" and "Tuesday — Picture Retakes" can both show. **What the class would care about, not the teacher's diary**: the calendar is one list for the whole school and much of it is marks due, rosters, report deadlines, a colleague out — those rows are marked `staffOnly` (`STAFF_ONLY` in `parse.ts`) and left out, though never a day off, whatever it is called. `?debug=1` prints both what shows and what was left out, so the list can be tuned. Three events a day at most — a banner, not the whole calendar
- **The calendar and the birthdays are read by name** (`SchoolCalendar!A1:G220`, `BDays!A1:AZ400`): both tabs are found in the cached tab list the way Kiss & Ride is, and read in the ordinary values batch, which costs nothing — a batch is one request however many ranges it carries. They used to arrive only because A2's notice rule named them, which made the balloons and the banner depend on how that rule happens to be written. The calendar is a row per event — A the date in words, B the same date as `"<serial> n"` (the key the sheet's own lookups match, `n` telling two events on one day apart), C the event, D `TRUE` for a day off, F a longer description — and BDays is keyed the same way. Columns are taken from the grid's own left edge, so a range a rule happened to name — `SchoolCalendar!B3:C200` — is still read as B and C
- **The anthem has its own flag.** `public/daily/flag-ca.svg` is vendored from flag-icons (MIT; the flag itself is public domain), used whenever the sheet's own `Poems!F3:J3` gives nothing. Canada's flag does not change, and the room should not be short of one because a picture was pasted into a cell the API cannot see
- At the end of the day the screen finishes on **the day's joke** where the verse used to be (`HOUSE_JOKES`, `jokeOfDay`, picked by the date so the room gets the same one all afternoon) — unless the sheet carries a blessing, which still takes that place. The verse has had the bottom bar all day
- The footer's weekday chip is set about twice the size it was: it is the one word on the board saying which day the room is looking at, and it was the smallest thing on the screen
- **The board reads what the rules name.** A slot rule can point anywhere — the term's cartoon is an INDEX down a column of addresses on a tab of its own — and a reference past the ranges the board reads throws, so the rule falls back to the value the sheet computed, which for a picture cell is nothing at all. That is why E1's cartoon never appeared. The ranges are now taken from the rules themselves (`referencedRanges`, `mergeRanges`, `rangeCovers` in `lib/daily/formula.ts`): every reference in `Setup!S1:AB8`'s formulas and in E1's own is checked against the fixed reads one by one — they reach all over Setup, and one box round the lot would look like a range nothing covers — and whatever is left over is read, merged to one range per tab. A whole column is capped at 400 rows and `INDIRECT("Flags!B3")`'s reference, being a string, is seen too. What is found is remembered on the cache (`extraRanges`, at most eight), so discovering a tab costs one extra request once and nothing on every refresh after; the grids come back through `extraGrids` — **values and formulas**, since a cell on one of those tabs may hold `=IMAGE("…")` and no text value at all — and are added to the book behind the ranges read by name. `?debug=1` prints them under "ranges the rules named"
- A picture in the feature cell E1 (`=IMAGE()`, hyperlink, or image URL — E1 is read as both value and formula) takes the large side of the screen while the sheet shows it; Drive links are rewritten for `<img>`, and an image that fails to load falls back to the normal panel. It reaches the screens either side of the teaching day too: during announcements it has the screen to itself, scaled up to fill it (the flag for the anthem) with "Please listen" underneath — that branch used to render a blank screen before E1 was ever consulted — and the before-school screen shows it beside the agenda whether or not the day's classes are known yet
- **Pictures the API cannot see.** The Sheets REST API has no image field at all: `CellData` carries formats, formulas, notes, hyperlinks and chips, `ExtendedValue` has no image type, and the discovery document has no image schema anywhere. A picture put *into* a cell with Insert > Image — either kind — therefore reaches the board as nothing, which is why the flag, the feature cartoon and the lesson pictures all read empty. The fix is in the sheet, and it leaves the cells alone: `frontend/src/app/daily/apps-script/mirror-cell-images.gs` finds the cells holding a picture, takes Google's temporary address, fetches the bytes while it is good, writes them to a Drive folder shared with anyone who has the link, and records the durable address on a hidden **BoardImages** tab — cell in column A, address in column B. The board reads `BoardImages!A2:B200` (`buildCellImages`, `cellImageKey`) and uses it wherever the picture itself cannot be seen: the anthem flag, the feature cell, a lesson's picture, and any Setup rule whose reference lands on a picture cell (`cellAt` in `formula.ts` falls back to it). A picture inserted from a URL keeps that URL; one pasted or uploaded is copied, because the projector is not signed in as the teacher and Google's own image URLs are tagged to the requester and expire within the hour. The bytes are fingerprinted, so an unchanged picture is not uploaded again and its address does not churn. A mirror column of the teacher's own is fine — the picture and video columns are told apart by content — but it only covers the Lessons tab, and a mirror written from `getContentUrl()` expires within the hour, so the recorded address is the durable route. Triggers cannot be bound to a column, so the handlers filter on the edited range; a picture insertion often arrives as a change rather than an edit, with no range to filter on, so the hourly time trigger is the dependable one
- `frontend/src/lib/daily/sheets.ts` — Sheets API via service account JSON (`DAILY_SHEETS_SERVICE_ACCOUNT`) or `DAILY_SHEETS_API_KEY`
- `frontend/src/lib/daily/parse.ts` — pure parser (DisplayAI rows, status text, points line, Setup labels)
- `frontend/src/app/daily/README.md` — env vars, ranges read, timing rules, test URLs

**Workflow for this feature:** changes to the daily board go all the way through without asking — commit, push, open the PR and merge it — so the board deploys. Stop and check first only for work outside `frontend/src/app/daily`, `frontend/src/app/api/daily` and `frontend/src/lib/daily`, or anything that could affect the grading pages.
